# 明辨 · 多 Agent 举证核证系统

几个 Agent 就同一个议题**举证对抗**:各自独立表态、交叉盘问、真去核实证据,
最后由一个独立判官**按证据质量**裁决 —— 而不是比谁说得漂亮。

```
你：多 Agent 协作到底有没有实效？

  判据     先定"什么算好"，全场共用，中途不许改
  举证     甲方、乙方**背对背**各自找证据（互不可见）
  盘问     交换后只准对**证据**开火，不准对结论开火
  核证     验证器真去打开原文，一条条判：证实 / 推翻 / 查不了
  裁决     按证据质量排，分三堆，保留异议
```

## 它和"多 Agent 群聊"的区别

群聊是**让它们聊**，这里是**让它们举证**。

差别落在一件具体的事上：**群聊里第一个开口的人会锚定所有人** ——
第二个人看到的已经不是原始证据，而是「第一个人的观点 + 原始证据」。
所以这里的**第一轮是背靠背的**，谁也不许看谁。

## 三个设计点

### 1. 证据分级，而且升级由**代码**卡

| 级 | 形态 | 怎么处理 |
|---|---|---|
| **L0** 断言 | "我觉得 / 通常来说" | 不算论据 |
| **L1** 引用 | "文档里写了 X" | 待核，不给分 |
| **L2** 可核验 | 给了**能直接打开的地址**（完整 URL / 文件路径） | 送验证器 |
| **L3** 已核验 | 验证器真打开了、对上了 | **才算事实** |

关键在 L2 那道闸门是**代码判的，不是模型自觉**：

- 声称可核验、却没给出处 → 直接打回 L0
- 出处抠不出可打开的地址（比如"去某某官网搜索XX"这种**给人看的指路说明**）→ 自动降级为 L1

实测模型很爱写后者。不卡的话，整个核证层会空转。

### 2. 同源证据合并取 max，**不累加**

一个人引三个来源，和三个人引同一个来源，是两回事。

> 同一份来源被引两次，不是两个证据，是**一个证据被数了两遍**。

按出处身份（URL 规范化 / 文件路径）分组，同组只记一次权重 ——
**相关观测不能当独立样本**。

### 3. 验证器盲判，而且优先读本地

- **盲判**：核验时**不告诉它这条证据是谁提的、那人的结论是什么**，只给「声称 + 原文」。
  否则它会被文辞带偏 —— 这跟交叉盘问要求匿名化是同一个道理，只是更彻底。
- **本地优先**：正文先看本地语料库里有没有存过。**不出门，就没有 403 / 超时 / 挂梯子那一串事。**

## 跑起来

```bash
pip install fastapi uvicorn requests psycopg2-binary
cp config.example.py config.py     # 填 API Key
py server.py
```

打开 http://127.0.0.1:5195

**辩论要求「来源独立」**：两个辩手必须是**不同模型家族**的，
判官和验证器也不能和辩手同一家。全用同一个模型，
那不是辩论，是同一个模型的自问自答 —— 启动时会警告你。

## 结构

```
server.py            服务 + 两种模式分发（辩论 / 会商）
debate.py            四个阶段
evidence.py          证据分级 / 同源判定 / 权重合并 / 取原文
aihot_db.py          本地语料库检索（可选，见下）
evidence_source.py   语料库 HTTP API（退化路径）
tools.py             辩手能调的工具
llm.py               模型调用（多供应商 + 工具循环 + 自愈重试）
config.py            密钥 / 座位 / 闸门
```

## 证据池（可选）

辩手可以带一个 `search_evidence` 工具，自己去检索、自己决定搜什么。

接的是本地部署的 [AIHOT](https://github.com/KKKKhazix/AIHOT) ——
它的 `articles` 表里存着**已经抓好的正文**，所以：

- 辩手给的地址是**真地址**，不是凭记忆编的
- 验证器能**在本地核**，不用出门

不接也能跑，只是辩手退回去靠记忆，证据会大量落在 L0/L1。

配置见 `config.py` 的 `AIHOT_BASE` / `AIHOT_DB_*`。
